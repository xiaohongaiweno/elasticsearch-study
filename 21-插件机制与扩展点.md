> 目标：讲清 ES 插件的**加载机制**（目录扫描 → jar hell 检查 → 类加载器 → SPI 重载）和**全部扩展点**，
> 让你能独立写一个插件、也能看懂 x-pack 是怎么把安全/监控/SQL 塞进 ES 的。
>
> **为什么必须学**：
> - 做云服务几乎必然要**自定义插件**（公司自研分词器、自定义聚合、鉴权拦截器、自定义存储）。
> - 插件是**唯一被官方支持的扩展方式**；改 core 源码意味着永远不能平滑升级。
> - 插件出问题的报错都很吓人（`jar hell`、`failed to load plugin`、`no public constructor`），
>   不懂加载机制就只能靠猜。
> - 插件崩溃会**导致整个节点起不来**（`BootstrapChecks` 之后的 `PluginsService` 抛异常）。
>
> **前置**：第 02 章（模块全景）、第 03 章（启动流程）、第 07 章（Action 框架）。
> **本篇对应**：阶段 5（生态期）。

## 3. 插件是怎么被发现的

### 3.1 三类来源

`PluginsService` 构造函数（`:103`）：

```java
// ① classpath 插件：给测试 / transport client 用
for (Class<? extends Plugin> pluginClass : classpathPlugins) {
    Plugin plugin = loadPlugin(pluginClass, settings, configPath);
    PluginInfo pluginInfo = new PluginInfo(pluginClass.getName(), "classpath plugin", "NA",
        Version.CURRENT, "1.8", pluginClass.getName(), Collections.emptyList(), false);   // :114
    ...
}

// ② modules/ —— 官方"模块"，默认内置（transport-netty4、lang-painless、reindex ...）
if (modulesDirectory != null) {
    Set<Bundle> modules = getModuleBundles(modulesDirectory);                            // :129
    ...
}

// ③ plugins/ —— 用户安装的插件
if (pluginsDirectory != null) {
    if (isAccessibleDirectory(pluginsDirectory, logger)) {
        checkForFailedPluginRemovals(pluginsDirectory);                                  // :144
        Set<Bundle> plugins = getPluginBundles(pluginsDirectory);                        // :145
        ...
    }
}
```

> **`modules/` vs `plugins/` 的区别**：
> 6.6.1 里两者**加载机制完全一样**（都是 `Bundle` + `URLClassLoader`），
> 区别只在目录和"是否默认随发行版打包"。
> 所以**模块能做的事，插件都能做** —— 这就是官方功能的"试验田"模式
> （先做成 module，成熟后（或商业化后）搬到 x-pack plugin）。

### 3.2 描述文件：`plugin-descriptor.properties`

`PluginInfo.ES_PLUGIN_PROPERTIES`（`:49`）：

```java
public static final String ES_PLUGIN_PROPERTIES = "plugin-descriptor.properties";
public static final String ES_PLUGIN_POLICY    = "plugin-security.policy";      // :50
```

`readFromProperties`（`:156`）读取的属性（**缺一个就启动失败**）：

| 属性 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 插件名（`plugin. mandatory` 检查用） |
| `description` | ✅ | 描述 |
| `version` | ✅ | 插件自身版本 |
| `elasticsearch.version` | ✅ | ★ 必须与 ES 版本**完全一致**，否则 `verifyCompatibility` 报错 |
| `java.version` | ✅ | 需要的 Java 版本（会被 `JarHell.checkVersionFormat` 校验） |
| `classname` | ✅ | ★ 插件主类全限定名 |
| `extended.plugins` | ❌ | 逗号分隔；声明本插件**扩展**了哪些插件 |
| `has.native.controller` | ❌ | 是否带 native controller 进程 |

末尾还有一道"不允许未知属性"的检查（`:238`）：

```java
if (propsMap.isEmpty() == false) {
    throw new IllegalArgumentException("Unknown properties in plugin descriptor: " + propsMap.keySet());
}
```

> **排障**：`"property [elasticsearch.version] is missing"` / `"Unknown properties in plugin descriptor"`
> → 手写或打包脚本生成的描述文件有问题。**版本必须精确匹配**，
> 这也是"ES 6.6 的插件不能装到 6.7"的原因。

### 3.3 移除残留检查

`checkForFailedPluginRemovals`（`:345`）：如果 `plugins/` 下存在 `.removing-<name>` 之类的残留目录会报错。
常见于**插件卸载失败**（`bin/elasticsearch-plugin remove` 中断）。

### 3.4 依赖拓扑排序

`sortBundles`（`:413`）：按 `extended.plugins` 做**拓扑排序**，保证被扩展的插件先加载。
`addSortedBundle`（`:424`）里检测循环依赖。

### 3.5 jar hell 检查（最容易踩的坑）

`checkBundleJarHell`（`:474`）：

```java
// ① 被扩展的插件之间不能有重复 codebase
Set<URL> intersection = new HashSet<>(urls);
intersection.retainAll(pluginUrls);
if (intersection.isEmpty() == false) {
    throw new IllegalStateException("jar hell! extended plugins " + exts +
        " have duplicate codebases with each other: " + intersection);          // :488
}
// ② 本插件与被扩展插件不能有重复 codebase
intersection = new HashSet<>(bundle.urls);
intersection.retainAll(pluginUrls);
if (intersection.isEmpty() == false) {
    throw new IllegalStateException("jar hell! duplicate codebases with extended plugin ["
        + extendedPlugin + "]: " + intersection);                               // :495
}
// ③ 不能与 core 有重复 codebase
Set<URL> intersection2 = new HashSet<>(classpath);
intersection2.retainAll(bundle.urls);
if (intersection2.isEmpty() == false) {
    throw new IllegalStateException("jar hell! duplicate codebases between plugin and core: "
        + intersection2);                                                       // :511
}
// ④ 也不能有重复类
Set<URL> union = new HashSet<>(classpath);
union.addAll(bundle.urls);
JarHell.checkJarHell(union, logger::debug);                                     // :516
```

> **`jar hell` 的本质**：同一个类（同名全限定名）出现在两个 classpath 条目里。
> 后果是"你以为加载的是 A 版本，实际是 B 版本"，这类 bug 极难排查，所以 ES 选择**启动期直接拒绝**。
>
> **最常见的触发**：插件把 `elasticsearch-x.x.x.jar`、`lucene-*.jar`、`log4j-*`、`jackson-*`
> **打进了自己的 fat jar**。这些必须在 `build.gradle` 里声明为 `provided`/`compileOnly`。

### 3.6 类加载器与 SPI 重载

`loadBundle`（`:522`）：

```java
// 收集被扩展插件的 classloader
List<ClassLoader> extendedLoaders = new ArrayList<>();
for (String extendedPluginName : bundle.plugin.getExtendedPlugins()) {
    Plugin extendedPlugin = loaded.get(extendedPluginName);
    if (ExtensiblePlugin.class.isInstance(extendedPlugin) == false) {
        throw new IllegalStateException("Plugin [" + name + "] cannot extend non-extensible plugin ["
            + extendedPluginName + "]");                                        // :533
    }
    extendedLoaders.add(extendedPlugin.getClass().getClassLoader());
}

// 建子加载器：parent = (core loader + 被扩展插件的 loaders)
ClassLoader parentLoader = PluginLoaderIndirection.createLoader(getClass().getClassLoader(), extendedLoaders);
ClassLoader loader = URLClassLoader.newInstance(bundle.urls.toArray(new URL[0]), parentLoader);   // :540

// ★ 用新 classloader 重载 Lucene SPI
reloadLuceneSPI(loader);                                                        // :543
for (String extendedPluginName : bundle.plugin.getExtendedPlugins()) {
    ExtensiblePlugin.class.cast(loaded.get(extendedPluginName)).reloadSPI(loader);   // :546
}

Class<? extends Plugin> pluginClass = loadPluginClass(bundle.plugin.getClassname(), loader);
Plugin plugin = loadPlugin(pluginClass, settings, configPath);
```

`reloadLuceneSPI`（`:560`）—— **顺序不能改**（源码注释明确写了 `do NOT change the order`）：

```java
// Codecs:
PostingsFormat.reloadPostingsFormats(loader);
DocValuesFormat.reloadDocValuesFormats(loader);
Codec.reloadCodecs(loader);
// Analysis:
CharFilterFactory.reloadCharFilters(loader);
TokenFilterFactory.reloadTokenFilters(loader);
TokenizerFactory.reloadTokenizers(loader);
```

> **为什么要重载 SPI**：Lucene 的 `Codec`/`PostingsFormat` 用 Java SPI（`META-INF/services`）发现实现，
> 而 SPI 默认只认**当前线程的 context classloader**（core 的）。
> 插件要在 jar 里注册自己的 Codec，就必须让 Lucene 用插件的 classloader 重新扫描一遍。

### 3.7 构造函数签名

`loadPlugin`（`:581`）反射构造：

```java
final Constructor<?>[] constructors = pluginClass.getConstructors();
if (constructors.length == 0) throw new IllegalStateException("no public constructor for [...]");   // :584
```

`signatureMessage`（`:612`）指出允许的签名（6.6.1）：

- `Plugin()` —— 无参
- `Plugin(Settings settings)`
- `Plugin(Settings settings, Path configPath)`

> **报错**：`no public constructor of correct signature for [...]`
> → 主类构造器不是 public，或参数不是这三种之一。

### 4.3 `updatedSettings`：feature 与额外配置

`PluginsService.updatedSettings`（`:199`）：

```java
for (Tuple<PluginInfo, Plugin> plugin : plugins) {
    Settings settings = plugin.v2().additionalSettings();
    for (String setting : settings.keySet()) {
        String oldPlugin = foundSettings.put(setting, plugin.v1().getName());
        if (oldPlugin != null) {
            throw new IllegalArgumentException("Cannot have additional setting [" + setting + "] "
                + "in plugin [" + plugin.v1().getName() + "], already added in plugin [" + oldPlugin + "]");  // :208
        }
    }
    builder.put(settings);
    final Optional<String> maybeFeature = plugin.v2().getFeature();
    if (maybeFeature.isPresent()) {
        if (features.containsKey(feature)) {
            throw new IllegalArgumentException("duplicate feature [...] in plugin [...]");   // :217
        }
        features.put(feature, plugin.v1().getName());
    }
}
for (final String feature : features.keySet()) {
    builder.put(TransportSettings.FEATURE_PREFIX + "." + feature, true);                     // :229
}
return builder.put(this.settings).build();                                                   // :231
```

两个关键结论：

1. **两个插件不能注入同一个 setting**（`additionalSettings` 冲突直接启动失败）。
2. **`getFeature()` 会被写进 settings**，变成 `transport.features.<feature>: true`，
   用于节点间能力协商（老节点不含某 feature 时，相关的 `ClusterState.Custom` 会被 `FeatureAware` 拒绝）。

## 6. 索引级扩展点：`IndexModule`

`index/IndexModule.java:85`。由 `Plugin.onIndexModule(IndexModule)` 回调
（`PluginsService.onIndexModule:259` → 每个插件一次）。

| 方法 | 行号 | 作用 |
| --- | --- | --- |
| `addIndexEventListener(listener)` | `:199` | ★ 索引生命周期事件（创建/关闭/删除/shard 状态变化） |
| `addSearchOperationListener(listener)` | `:222` | 每次搜索的前后钩子 |
| `addIndexOperationListener(listener)` | `:245` | 每次索引/删除的前后钩子 |

| `forceQueryCacheProvider(...)` | `:456` | 替换 query cache |
| `addSettingsUpdateConsumer(...)` | `:146`/`:157` | 监听索引 setting 变更 |

关键字段（`:109-119`）：

```java
private final IndexSettings indexSettings;
```

> 这也是 DLS 会**显著拖慢查询**的原因。

## 7. 写一个插件：完整骨架

### 7.1 插件主类

```java
package com.example.es.plugin;

import org.elasticsearch.plugins.Plugin;
import org.elasticsearch.plugins.ActionPlugin;
import org.elasticsearch.plugins.SearchPlugin;
import java.util.*;

public class ExamplePlugin extends Plugin implements ActionPlugin, SearchPlugin {

    // ① 构造函数必须是这三种签名之一
    public ExamplePlugin(org.elasticsearch.common.settings.Settings settings) {
        this.settings = settings;
    }

    // ② 声明 setting
    @Override public List<Setting<?>> getSettings() {
        return Collections.singletonList(EXAMPLE_TIMEOUT_SETTING);
    }

    // ③ 注册 Action + REST
    @Override public List<ActionHandler<? extends ActionRequest, ? extends ActionResponse>> getActions() {
        return Collections.singletonList(
            new ActionHandler<>(ExampleAction.INSTANCE, TransportExampleAction.class));
    }

    @Override public List<RestHandler> getRestHandlers(Settings settings, RestController restController,
            ClusterSettings clusterSettings, IndexScopedSettings indexScopedSettings,
            SettingsFilter settingsFilter, IndexNameExpressionResolver resolver,
            Supplier<DiscoveryNodes> nodesInCluster) {
        return Collections.singletonList(new RestExampleAction(settings, restController));
    }

    // ④ 注册自定义聚合
    @Override public List<SearchPlugin.AggregationSpec> getAggregations() {
        return Collections.singletonList(new AggregationSpec(
            ExampleAggregationBuilder.NAME,
            ExampleAggregationBuilder::new,
            ExampleAggregationBuilder.PARSER)
            .addResultReader(InternalExample::new));
    }

    // ⑤ 需要长期存活的服务
    @Override public Collection<Object> createComponents(Client client, ClusterService clusterService,
            ThreadPool threadPool, ResourceWatcherService resourceWatcherService,
            ScriptService scriptService, NamedXContentRegistry xContentRegistry,
            Environment environment, NodeEnvironment nodeEnvironment,
            NamedWriteableRegistry namedWriteableRegistry) {
        ExampleService service = new ExampleService(settings, clusterService, threadPool);
        return Collections.singletonList(service);
    }
}
```

### 7.2 `plugin-descriptor.properties`

```properties
description=Example plugin for ES 6.6.1
version=1.0.0
name=example
classname=com.example.es.plugin.ExamplePlugin
java.version=1.8
elasticsearch.version=6.6.1
extended.plugins=
has.native.controller=false
```

### 7.3 安装

```bash
bin/elasticsearch-plugin install file:///path/to/example-1.0.0.zip
# 安装后目录：plugins/example/{plugin-descriptor.properties, example-1.0.0.jar, ...}

bin/elasticsearch-plugin list
bin/elasticsearch-plugin remove example
```

**强制插件必须存在**（`MANDATORY_SETTING`，`PluginsService:85`）：

```yaml
plugin.mandatory: [example]
```

缺失时报错（`PluginsService:173`）：`"missing mandatory plugins [example], found plugins [...]"`，**节点拒绝启动**。

## 9. 排障手册

### 9.1 启动失败的常见原因

| 报错 | 原因 | 位置 |
| --- | --- | --- |
| `jar hell! duplicate codebases between plugin and core` | fat jar 里打包了 ES/Lucene 依赖 | `PluginsService.java:511` |
| `failed to load plugin [x] due to jar hell` | 同上（外层包装） | `PluginsService.java:518` |
| `Plugin [x] cannot extend non-extensible plugin [y]` | 被扩展的插件没实现 `ExtensiblePlugin` | `PluginsService.java:533` |
| `no public constructor for [...]` | 主类无 public 构造器 | `PluginsService.java:584` |
| `no public constructor of correct signature for [...]` | 构造器参数不是 `()`/`(Settings)`/`(Settings, Path)` | `PluginsService.java:615` |
| `property [elasticsearch.version] is missing` | 描述文件缺字段 | `PluginInfo.java:187` |
| `Unknown properties in plugin descriptor: [...]` | 描述文件多了字段 | `PluginInfo.java:239` |
| `missing mandatory plugins [...] , found plugins [...]` | `plugin.mandatory` 里的插件没装上 | `PluginsService.java:173` |
| `Cannot have more than one plugin implementing a REST wrapper` | 两个插件都实现了 `getRestHandlerWrapper` | `ActionModule.java:382` |
| `Cannot have additional setting [x] in plugin [a], already added in plugin [b]` | 两插件注入同名 setting | `PluginsService.java:208` |
| `Unable to initialize modules/plugins` | 目录不可读 / IO 错误 | `PluginsService.java:135`/`:153` |
| `Could not find plugin class [...]` | `classname` 写错或类不在 jar 里 | `PluginsService.java:577` |
| `duplicate feature [x] in plugin [a], already added in [b]` | 两插件声明同名 feature | `PluginsService.java:217` |

### 9.2 排查步骤

```bash
# 1) 看插件是否被识别
GET /_cat/plugins?v

# 2) 看节点启动日志里 "loaded module/plugin"
grep "loaded plugin\|loaded module" logs/*.log

# 3) 看插件的 feature / settings 是否生效
GET /_nodes/settings?include_defaults=true

# 4) 检查 jar 冲突（在插件目录里）
unzip -l plugins/example/example-1.0.0.jar | grep -E "org/elasticsearch|org/apache/lucene"
#   ↑ 这里如果非空，就是 jar hell 的元凶

# 5) 校验描述文件
cat plugins/example/plugin-descriptor.properties
```

### 9.3 版本升级的坑

`verifyCompatibility`（`PluginsService:337`）要求 `elasticsearch.version` **精确匹配**。
所以：

- 升级 ES 版本 → **必须同步升级所有插件**（尤其是分词器，涉及 Lucene 版本）。
- 灰度升级期间，集群里**新旧节点插件不一致**会导致 feature 协商失败
  （`transport.features.<name>` 缺失 → `ClusterState.FeatureAware` 拒绝）。
